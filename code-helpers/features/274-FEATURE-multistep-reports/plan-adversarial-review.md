# 274 — Adversarial review of the TDD implementation plan

> Attack of `tdd-implementation-plan.md` against `analysis.md` (D1–D17), `.agents/skills/miroir-analysis-to-tdd-plan/SKILL.md`, and the current codebase on branch `274-FEATURE-multistep-reports`. Product decisions D1–D17 are not relitigated; slice verticality, RED runnability, GREEN feasibility/ordering, test-vehicle choice, UUID/asset feasibility, and factual claims are. Every citation below was walked against the working tree on 2026-09-13.

**Applied:** 2026-09-13 — all P1–P16 ticked below and written into the revised `tdd-implementation-plan.md` (MiroirTest integ vehicle + nested template wrapper; tracer frozen in Slice 1; Slice 4/5 own Reports; three nonreg steps).

**Verdict.** The plan is a faithful translation of the repaired analysis into a slice list: the tracer story is the right one (a Library Report whose Finish template builds a Country from the step bag is the thinnest end-to-end proof of D1–D5), the locked-defaults table matches the analysis decision record verbatim, every slice carries Status/RED/GREEN/Refactor/Validation with no commit lines, and the final slice is compliant (nonreg + docs + #238 cleanup + AC). It is **not implementation-ready**. Four blockers: (1) the Slice 1 tracer — the primary proof of the whole feature — is validated with a command that cannot run it (`testMiroir -w miroir-core --mode unit` rejects `actionTest` leaves; the suite must run from miroir-standalone-app in integration mode); (2) the tracer leaf as specified cannot exist — an `actionTest` leaf carries a *resolved* `CompositeActionSequence` and its `testParams` are dropped, so the `getFromParameters` template and the `{ stepOne: … }` bag have no wired mechanism; (3) Slice 0 locks three assertions that Slice 1 GREEN flips (enum, `RootReport.compositeActionSequence`, seed count 84→85) and only one flip is scheduled for in-place consumption; (4) the new Library Report asset is never registered in `Library.ts`'s `defaultLibraryAppModel`, so no integration session will ever contain it. Six majors compound this: the RED rationale cites an enum validation that does not exist in `jzodTypeCheck`, every RTL integ Validation command omits `--profile` and dies at config load, Slice 2's Finish assertion requires a spy under a "No mocks" header, the tracer Report asset is mutated across Slices 2–3 without scheduling, the Slice 5 grid tools column is a hardcoded triple-action renderer in *two* grid implementations with no section-definition plumbing, and the nonreg manifest entries reference a MiroirTest unit mode that does not exist.
