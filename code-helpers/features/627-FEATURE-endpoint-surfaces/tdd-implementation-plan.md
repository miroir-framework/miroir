## Test execution conventions

| Purpose | Command |
|---|---|
| MCP tests (`test-filesystem` by default) | `npm run testByFile -w miroir-mcp -- <name>` |
| CLI tests | `npm run testByFile -w miroir-cli -- <name>` |
| CopilotKit tests | `npm run testByFile -w miroir-ai -- <name>` |
| Core unit tests | `npm run testByFile -w miroir-core -- <name>` |
| Fixture model validation | `npm run testByFile -w miroir-fixture-appForTest -- modelValidation` |
| Fixture rebuild after a TS export change (test environments copy `assets/` directly) | `npm run build -w miroir-fixture-appForTest` |
| Core rebuild (consumers read `dist`) | `npm run build -w miroir-core` |
| Type check | `npx tsc --noEmit --skipLibCheck -p packages/<pkg>/tsconfig.json` |
| Repo script tests | `python -m pytest scripts/tests -q` |
| Scoped nonreg | `npm run nonreg:filesystem -- --runner shared --scope smoke,<scopes>` |

Vitest is the vehicle throughout: the behaviour under test is a package surface (an MCP tool list, a `commander` program, a CopilotKit action list and Express route), which no MiroirTest reaches. The fixture Endpoint is the applicative interface and is proven by the fixture's `modelValidation`.

## Slice 4 — CopilotKit actions from the catalog

**Status:** ⬜ pending

### Goal

### 4.1 RED — action list, execution, route

**Test:** `packages/miroir-ai/tests/integration/issues/627-endpoint-surfaces/copilotKitEndpointActions.627.phase4.integ.test.ts`, on a new `tests/integration/aiTestPlatform.ts` that boots `test-filesystem` like `miroir-mcp/tests/integration/mcpTestPlatform.ts`, with its own store startup (miroir-mcp's `src/startup` is not importable). `miroir-env`, `miroir-localcache-redux`, `miroir-store-filesystem` (and `miroir-app-admin` if the setup needs it) become `miroir-ai` devDependencies; `npm install` refreshes the lockfile. - `createMiroirCopilotKitActions(domainController, map, authentication)` contains `appForTest_fixtureCreateItem` and `Library_lendDocument`, no name starting with `Miroir_` or `Admin_`, and still `generateMiroirReport` and `getMiroirContext`.
- Calling the fixture action's handler creates the Country.
- `POST endpointAction/appForTest_fixtureCreateItem` on the router (authentication off) succeeds; `POST endpointAction/Miroir_createInstance` returns 404.
- With `authenticationEnabled: true` and `req.miroirAuthentication` set by the test (as the identity middleware does): a principal without a grant on the fixture deployment gets 403 and no Country is created; a principal with one succeeds, and the principal reaches `handleAction` (the created Country is visible, the call is not denied).

- `mountCopilotKitRoute.ts` and Electron `ipcServerSetup.ts` pass `authenticationEnabled`; `AiActionsProvider.tsx` posts to `endpointAction/Library_lendDocument`.
