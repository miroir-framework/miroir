# UI architecture review: log of the second validation round

Date: 2026-10-06, plain-language edit on 2026-10-23. Code base: `_integration` at `9838983`, the same commit as revision 1. This log lists what the second round changed in `analysis.md`. Everything it does not list was checked again and still holds.

Paths are relative to `packages/miroir-standalone-app/src/miroir-fwk/4_view/` unless a package path is given.

## How it was checked

- Three separate read-only reviews each tried to prove one part of the claims wrong. The first covered the editors and the code structure (sections 2.2 to 2.5, U9 to U19). The second covered dependencies, dead code, CI and the metrics (section 2.1, U20 to U29, appendix). The third covered the guidance available to agents (sections 4 and 5.3). I checked the data flow findings (U1 to U8) and the read and write paths (sections 2.6 to 2.8) again myself, against `DomainController.ts`, `CallUtils.ts`, `PersistenceReduxSaga.ts` and the selector code.
- `tsc --noEmit` ran on the app, `miroir-react`, `miroir-diagram-class` and both local caches. The first run reported 57 errors in the app. 25 of them came from an outdated `miroir-core/dist` in this container, built before #449 and #472. After `npm run build -w miroir-core`, the app reports 36 errors (32 about MUI, and 4 about workspace packages that are not linked in this container) and the libraries report none.
- Every Mermaid diagram was rendered in headless Chromium with Mermaid 11.12.3, and all of them parse. Diagram 2.5 was redrawn because its edges crossed too much to read, and the boxes of diagram 2.1 were grouped differently.
- All claims about behaviour come from reading the code. Nothing was measured in a running app.
